## 2. Contract under test

`IngestionEngine(db: AsyncSession)` exposes:

| Member | Observed behaviour |
|---|---|
| `_validate_extension(name)` | raises `InvalidFileExtensionError` when name is empty/has no `.`, or suffix ∉ {`.txt`,`.cfg`,`.conf`,`.zip`}; otherwise returns silently |
| `_validate_size(content)` | raises `FileTooLargeError` when `len(content) > 10_485_760` |
| `_calculate_hash(content)` | `sha256(content).hexdigest()` over raw bytes |
| `_decode_content(content)` | `utf-8` → `latin-1` → `cp-1252`, returns `(text, encoding)` |
| `_check_duplicates(hash)` | `SELECT` on `Configuration.content_hash`, raises `DuplicateConfigurationError` |
| `ingest(...)` | validates → decodes → hashes → dedups → `db.add(...)` → **returns `IngestionResult`, does not flush** |
| `IngestionResult` | `(configuration_id, filename, content_hash, size_bytes, line_count, encoding)` — no content field |

Callers: **zero**. `grep` for `app.engines.ingestion` / `IngestionEngine` across `backend/app/**` and `backend/tests/**` returns nothing outside the engine module itself and this validation harness.

## 7. Findings

| # | Finding | Class | Evidence | Recommendation |
|---|---|---|---|---|
| F1 | `FileDecodeError` can never be raised; the `cp-1252` fallback and the `raise` are unreachable, so binary input silently becomes text | MISSING | V01-24, V01-12 | Either fail closed on binary-looking input or delete the dead branch and document `latin-1` as a guaranteed fallback |
| F2 | Filename length is never checked against `Configuration.filename String(255)`; violation surfaces as an untyped `DBAPIError` | MISSING | V01-30, V01-19 | Validate `len(filename) <= 255` inside the engine |
| F3 | NUL bytes in decoded content reach the database and fail as `CharacterNotInRepertoireError`, escaping `ingest()` untyped | MISSING | V01-40 | Reject control characters during decode, or translate driver errors into `IngestionError` |
| F4 | No binary/magic-byte detection at ingestion; `ValidationEngine`'s `BINARY_CONTENT` check runs much later in the audit pipeline | DESIGN LIMITATION | V01-34 | Reuse the validator's heuristic at ingestion time, or document the deferral |
| F5 | `.zip` is advertised in `ALLOWED_EXTENSIONS` but no archive is ever opened; size is enforced on compressed bytes | DESIGN LIMITATION | V01-15, V01-16 | Implement bounded extraction, or drop `.zip` from the allow-list |
| F6 | Filenames are never normalised to a basename; `../../etc/passwd.cfg`, `..\..\windows\system32\evil.cfg` and NUL-containing names are accepted verbatim | CONFIRMED BEHAVIOR | V01-17 ×5, V01-18, V01-35 | `os.path.basename()` + control-character rejection before persistence |
| F7 | `content_type` is an unvalidated caller string (only `None`/`''` fall back to `text/plain`) | CONFIRMED BEHAVIOR | V01-20, V01-27 | Derive the type from the validated extension rather than trusting the caller |
| F8 | Zero-byte configurations are accepted and persisted with `line_count=0` | DESIGN LIMITATION | V01-31 | Decide explicitly and encode the decision in the contract |
| F9 | `IngestionEngine` is imported by nothing; the production upload path re-implements the same logic with different semantics | DESIGN LIMITATION | V01-37 | Route the endpoint through the engine, or delete the engine so one contract exists |
| F10 | `ingest()` returns an id with no content, while `AuditExecutor.execute()` requires `config_content: str`; the hand-off is mediated entirely by a database read neither module performs | DESIGN LIMITATION | V01-38 | Document the persistence-mediated hand-off, or return the decoded content alongside the id |
| F11 | `ingest()` never flushes; durability depends entirely on the caller committing | CONFIRMED BEHAVIOR | V01-26, V01-32 | Not a defect — record it in the contract, since a failure after return but before commit loses the row |

### Integration observations (outside Engine 01 scope, not tested)

Reported for the Integration contract review, per agreed scope:

- `app/api/v1/configurations.py:67-144` implements its own extension / size / hash / duplicate / decode logic.
- Duplicate: endpoint **returns the existing row** (`:103-109`); engine **raises** (`ingestion.py:185-189`).
- Decode: endpoint `utf-8 → latin-1` (`:111-123`); engine `utf-8 → latin-1 → cp-1252` (`:198-213`).
- Extension: endpoint maps extensionless names to `file_ext=''` → HTTP 400 (`:82-87`); engine raises `InvalidFileExtensionError('Invalid filename')`.
- Ordering: endpoint `await file.read()` (`:90`) buffers the entire body **before** the size check (`:94`).

## 9. Limitations of this validation

1. Only `backend/app/engines/ingestion.py` was exercised. The upload endpoint was read for divergence, not run.
2. DB-backed tests ran against a throwaway PostgreSQL database, not the deployed one; `String(255)` and NUL errors are PostgreSQL-specific and could differ on another backend.
3. Dataset sweep used pure helpers only, so duplicate rejection (81 files) is derived from observed `content_hash` collisions, not from 480 live `ingest()` calls.
4. Performance figures are single-machine measurements and are reported as measurements only.

---

## 10. Verdict

**PARTIAL.**

- **PASS** — hashing, size enforcement, extension allow-listing, typed errors for the declared failure modes, content-addressed deduplication, determinism (0 mismatches over 480 files × 2 passes), and performance.
- **PARTIAL** — security surface (F6, F7), archive handling (F5), empty-input contract (F8), downstream hand-off (F10).
- **FAIL** — error contract (F1, F2, F3: three failure modes escape as untyped or unreachable) and integration reality (F9: the engine is not used by production code).

Blocking for readiness: **F9** (single ingestion contract), **F2/F3** (typed failure surface).
